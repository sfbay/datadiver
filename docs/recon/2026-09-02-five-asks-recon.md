## A-311-cap — The Last 48 (/live) 311 super-chip "5,000" — silent FULL_LIMIT row cap in useLast48Window and every consumer that treats the sample as the window


### What is true today

useLast48Window (src/hooks/useLast48Window.ts) runs a two-phase fetch per stream. HEAD: `$where {dateField} >= sfLocalCutoff(now-6h)`, `$order {dateField} DESC`, `$limit 200` (HEAD_WINDOW_MS/HEAD_LIMIT lines 67-68; phase pick 295-296; query built 310-316). FULL/poll: identical shape with a 48h cutoff and `$limit 5000` (FULL_LIMIT line 69; WINDOW_MS line 39), options `{ skipCache: true, timeoutMs: 18000, retries: 2 }` (line 324; constants 78-79). No `$select` — every column comes back (client.ts:90-94 spreads params over `$limit: 1000` default; measured 1,080 bytes/row for 311). Polls: 911 every 2 min, Fire/EMS and 311 every 30 min (82-86), backfills staggered 0/700/1400 ms (80, 395). The result is merged into `byId` (333-351: `new Map(state.byId)` then `set` each normalized row), then ONLY this dataset's rows older than 48h are evicted (354-359). Nothing ever compares `rows.length` to `limit`; `Last48WindowResult` (108-136) has no `truncated`/`totalInWindow` field, and fetchDataset returns a bare `T[]` with no headers (client.ts:131-134). So on a fresh load each stream's event set is exactly the NEWEST min(5000, N) rows in the window — the OLDEST rows are what's lost — and no consumer can tell. Consumers then read `events.length` as the window count: DatasetSuperChips (244 count, 245 per-hour = count/48, 246-248 + 164-174 sparkline bins, 334/337 render, 258 aria-label), the header pill (Last48.tsx:374-378), FlowRail's big number (FlowRail.tsx:180) and no-GPS count (119), summaryStore seeding (Last48.tsx:156-164 writes `byDataset[id].length` once `fullyLoadedByDataset`), and — most consequentially — useAnomalyBaseline's CURRENT 48h counts, which are tallied from `opts.currentEvents` (useAnomalyBaseline.ts:164-170) while the BASELINE is a server-side GROUP BY with `$limit 50000` (96-107); `computeAnomalies` reads a missing neighborhood count as 0 = "quiet" (anomalyStats.ts:89, 104). Those anomalies drive AnomalyRail/AnomalyFillLayer/Last48NeighborhoodPeek (Last48UnifiedView.tsx:145-149, 160-170, 223-237, 286-293), the heartbeat detectors (Last48.tsx:219-224 → detectors.ts), and the Pulse wire, which mounts its OWN useLast48Window instance with the same cap (usePulseWire.ts:40-45).

### Constraints

- CLAUDE.md 'Server-side truth': never trust a client-side sample to represent a dataset — a count shown as the window total must come from a server aggregate, not `events.length`.
- Data-transparency principle (memory feedback_data_transparency_principle): every figure is PRESENT (true), SUPPRESSED (withheld with the reason stated), or ABSENT ('—'); a capped '5,000' rendered as a plain count is none of these.
- DataSF datetimes are floating SF-local strings — any new count/page query must build its cutoff with sfLocalCutoff (useLast48Window.ts:305-311; sfTime.ts), never toISOString().
- fetchDataset only builds an AbortController when timeoutMs is passed (client.ts:118-119) — every added heavy query needs timeoutMs/retries; the full fetch already carries 18s/2 (useLast48Window.ts:78-79, 324) and its comment documents the cold-load burst as ~7x slower at the browser's per-host connection limit (71-80) — extra requests per poll spend those slots.
- fetchDataset's aggregate regex (client.ts:88) auto-drops defaultSort for `count(*)` selects — reuse the useLast48Pulse.ts:52-56 query shape rather than hand-building a URL.
- The DATASET_REGISTRY_KEY / DATE_FIELD tables are duplicated in useLast48Window.ts:91-102, useAnomalyBaseline.ts:71-80 and useLast48Pulse.ts:38-42 (duplicated-allowlist drift memory) — a count query should read ONE shared table, not a fourth copy.
- Reader-facing copy must stay jargon-free — pulsePhrase's test fails the build if σ/z-score/baseline reaches reader text; chip copy must be plain ('newest 5,000 of 5,485'), and /about#whats-unusual is the only page allowed to name the machinery.
- The anomaly gate contract: useAnomalyBaseline takes `freshness` as REQUIRED and suppression is asymmetric (busy survives, quiet is unprovable — anomalyStats.ts:117-139); a truncation gate must have the same shape and live centrally in the hook so the Pulse card and its evidence map cannot disagree.
- StreamCurtain/chip sheen gate on `fullyLoadedByDataset` (FlowMapLayer.tsx:255-271; Last48.tsx:325-345) — any added page or count query must not delay or re-flip that flag.
- Publish-lag 'not here yet' zones use the diagonal-hatch idiom (DatasetSuperChips.tsx:43-55; memory feedback_hatch_zone_idiom) — an 'oldest hours not loaded' zone should reuse that grammar on the sparkline's left edge, not invent a new mark.
- Tier-3 glow rule: any new disclosure line is prose/chrome — no glow. Micro type via text-nano/micro/label tokens; `desk:` not `md:`; the chip's freshness row is already hidden below desk: (DatasetSuperChips.tsx:360-362), so a disclosure must survive the lean mobile chip.
- The corrections log (src/views/About/corrections.ts) is APPEND-ONLY and test-pinned; an entry is warranted only if a figure served from main was wrong AND a reader could have quoted it — Jesse's call, not the implementer's.
- /live carries no global date params (useUrlSync strips them) and must stay era-free — do not route a fix through the date picker.
- Only read-only work was done here: no files modified, no pnpm dev; curl GETs against data.sfgov.org only.
