# SF Ethics Commission campaign-consultant e-filing family — recon memo

**For:** Jesse · **Re:** DataDiver CampaignFinance view — next data source · **Pulls:** 2026-08-14 against live `data.sfgov.org` (SODA) · **Method:** 14 profiling passes (one per dataset group) → 5 cross-checks → draft → 3 adversarial verifiers (numbers / join-logic / completeness), corrections folded in below.

Everything the Ethics Commission publishes as data lives on **DataSF (Socrata)** — the same SODA API DataDiver already reads live. `sfethics.org/disclosures/campaign-finance-disclosure` is a directory that points at DataSF ids and says outright "use the SODA API". No hosting, no copies, provenance stays with the city. (NetFile's `public.netfile.com/pub2/?aid=sfo` exports exist but are a vendor site with no proper API; DataSF's `pitq-e56w` is the cleaned form of the same filings — skip NetFile.)

---

## 0. Verdict

The new campaign-consultant family (parent `iv34-5p9x` + 8 child tables joined on `envelope_id` + the stand-alone `acwz-2ua3` + 8 pre-joined DataSF views) is **small** (260 filings, 90 name spellings, ~$17.5M of reported client receipts after collapsing restatements, since the Sep–Nov 2024 quarter), **structurally clean where it is keyed** (0 orphan child rows; every child sum reconciles to its parent total to the cent), and **dirty everywhere it is not** — free-text names, no FPPC/committee id anywhere, filer-declared amendment flags that under-detect, Termination Reports that restate Quarterly totals, and three disclosure sections (city contracts, city appointments, employing officeholders) that are 0-for-260 after 20 months of mandatory e-filing.

Its real value is not as a standalone ledger but as the **other side of `pitq-e56w`**: matched on money rather than names, consultant-reported receipts and committee-reported Schedule E payments (the committee's own "who we paid" list) reconcile at **1.02** for the top ten (Schedule E only) — which is exactly what makes the exceptions reportable: a ~$1.35M Merrill Strategy Group absence, The Media Company reporting 18% of what SF Believes paid it in 2026 after 97% in 2024, $240K routed through a consultant into the June 2026 measure fights, and quarterlies filed by consultants with no registration on record.

**Recommendation:** do NOT build a standalone "Consultants" view. Build a **two-sided reconciliation lens inside CampaignFinance**, on top of two committed hand-authored crosswalks (consultant aliases; client string → `filer_nid`), with a precomputed reconciliation JSON rather than live per-consultant `pitq` queries — and pick up the free `filer_nid`-keyed enrichments (`4c8t-ngau`, `9ggq-m8hp`, `qizs-bwft`) at the same time. First artifact after this memo: the two crosswalk JSONs plus a probe script that re-derives §3–§4, before any UI.

## 2. How the tables fit together

**One envelope = one filing version.** The parent `iv34-5p9x` has 260 rows = 260 distinct `envelope_id` (DocuSign envelope GUID) = 254 distinct `filingseries`. `filingseries` is a composed string `'<campaignconsultantname>_<reporttype>_<M-D-YYYY of reportingperiodstartdate>'` — verified byte-exact on all 260 rows — so it groups versions of the same report but also splits whenever the consultant's name is spelled differently. `filinginformation_reporttype` says WHICH FORM (Quarterly Report 172 · Initial Registration 32 · Termination Report 29 · Reregistration 27); `filinginformation_filingtype` says which VERSION as the filer declared it (Original 255 · Amendment 5). The parent has **no `entry_id`** column despite its own description; `envelope_id` is the row key.

**Children hang off `envelope_id`.** Every child row carries `envelope_id`, `filingseries` and `entry_id = '<envelope_id>-<n>'` with a per-table ordinal — so `entry_id` never cross-joins siblings. Column names are the long DocuSign-flattened form (`clientlist_economicconsiderationreceived`, `filinginformation_reportingperiod_reportingperiodstartdate`); short forms 400 with `no-such-column`. `acwz-2ua3` is NOT a child: its 130 `envelope_id`s share zero values with the parent, its `filingseries` grammar is different (`'<Consultant>_<Client truncated ~20 chars>_<Auth|Term>_<MM-D-YYYY>'`, day unpadded on 50 rows), and the only cross-links are free-text consultant and client names.

**Amendment semantics.** An amendment is a NEW `envelope_id` with the SAME `filingseries`; the parent KEEPS the superseded envelope. Exactly 6 `filingseries` carry 2 envelopes: 5 Original→Amendment pairs (Margaux Kelly Q 9-1-2024 $30,000→$31,147.50; The Media Company Q "12-1-2026" $10,000→$10,000; Democratic Direct Rereg 1-1-2026 "add employees"; Rishav Rout Q 3-1-2026 contributions $0→$5,000; Stearns Consulting Q 3-1-2026 client total $0→$37,500) plus one double-submitted Original (Christian Kropff Initial Registration 9-16-2025, two envelopes 1h54m apart, byte-identical otherwise, no amendment marker). `filingtype` is unreliable as a version marker: 4 rows typed 'Original' also carry `originalfilingdate`/`descriptionofamendment` (Lian Chang, Ravinett, The Media Company Q 3-1-2026 "amending consultant name to firm" — whose person-named predecessor is not in the table — and Margaux Kelly with an `originalfilingdate` of 2024-02-01). Amendment detection must be structural. `acwz-2ua3` has the same shape: 2 Amendment pairs + 1 double-Original (Joseph Sweiss, 15 s apart); one amendment moves a termination date 2024-11-30 → 2025-02-28, so its raw 65/65 counts include superseded versions.

**The latest-version rule:** per `filingseries`, keep the row with `MAX(datesigned)`. It selects exactly 254 parent rows, has no ties in any chain, and equals the "prefer Amendment, then latest" rule on every series. Server-side, `data.sfgov.org` accepts a window function plus the `|>` chained subquery on this dataset (verified: `$query=SELECT …, row_number() OVER (PARTITION BY filingseries ORDER BY datesigned DESC) AS rn |> SELECT count(*), sum(clientinformation_total) WHERE rn=1` → `{n: 254, tot: 18458137.24}`); the universal fallback is `$select=filingseries,max(datesigned)&$group=filingseries` plus a client-side join, or pull all 260 rows and dedupe locally. **Caveat the rule honestly:** `filingseries` embeds two filer-typed fields (name spelling, period start), so an amendment that CORRECTS the name (exactly what `ce330cde` says it did) or the mis-keyed "12-1-2026" period lands in a NEW series and survives beside the original; `originalfilingdate` is the only bridge and is populated on 9 rows. Pin the standing test as *(rows − superseded) == distinct `filingseries`*, not the literal 254 of 260 — the literal breaks at the next filing deadline.

**What dedupe buys, in dollars.** Parent `sum(clientinformation_total)` all rows = $18,498,137.24; latest-per-series = $18,458,137.24; overcount exactly $40,000 (Margaux Kelly $30,000 + The Media Company $10,000). Contributions +$1,000 (Stearns), gifts +$250 (Margaux Kelly), vendors +$0. Small. The LARGER overcount is a different mechanism the amendment rule does not touch: **Termination Reports restating Quarterly totals for the same period.** With names normalized (case/punctuation — a strict same-string rule misses one), there are **5 exact pairs among latest rows = $451,553.42** (Margaret Heisler $30,500; SGR Consulting $403,889.62; Katherine Waters $7,425; Rodney Leong $738.80; Riff City Strategies, Inc / Inc. $9,000) plus the AGENCY pair ($449,484.50 on a Termination 9-1-2024 AND on a Quarterly whose period is 2025-09-01→11-30, signed 14 minutes apart on 2025-03-05), plus two same-period NON-identical restatements the exact rule ignores (John Dennis Q $5,000 vs T $10,000; Heidi L Sieck Q $30,000 vs T $31,267.53 with a shorter period). Restatement also duplicates CHILD rows outside clients: Heisler's $250 Peskin contribution sits under both her Q and T envelopes; Heidi Sieck has gift rows under both. Certain restated child dollars: **$497,148.30 (2.8% of the $18,054,247.62 child total)** + up to $35,000 ambiguous — so the collapsed client-receipts figure is **≈$17.52–17.56M**, and any headline must say which basis it uses.

**Do the DataSF joined views dedupe? No — and yes by accident.** Each view's `.queryString` is `SELECT … FROM iv34-5p9x JOIN @<child> ON envelope_id = @child.envelope_id ORDER BY datesigned DESC NULL LAST` — a bare INNER JOIN, no WHERE, no DISTINCT, no GROUP BY (`.query` is `{}`, `.metadata.jsonQuery` null). But the child tables carry ZERO rows under any superseded envelope (measured 0 in all 8 children and all 8 views), so today `sum(all child rows) == sum(latest-only child rows)` for every child. Whether SFEC deletes superseded list rows on amendment or never published them cannot be told from Socrata: the tables are append-only and children arrive ~1 s after every observed parent, yet the superseded originals that declare a total have zero child rows while their amendments' child rows carry the amendment's own `:created_at` — deletion leaves no trace. A builder can settle it prospectively by polling `:created_at` around the next amendment. Builder rule regardless: join child→parent on `envelope_id` and gate on the latest envelope per `filingseries`.

## 3. Data quality

**Join integrity:** 0 orphan child rows across all 8 tables (127+22+4+6+1+1+1+29 distinct child envelopes all resolve). Parent `envelope_id` unique 260/260, so the inner join can never fan out; joined-view row counts equal child row counts.

**Conservation:** wherever a child has rows, `Σ child amount == parent total` EXACTLY — clients 127/127, contributions 22/22 (vs `subtotalofitemizedcontributions`), vendors 4/4, gifts 6/6; largest discrepancy $0.00. Parent `itemized + unitemized == totalcontributions` on all 260 rows. Family-level gaps are therefore whole missing envelopes only: clients $18,498,137.24 (parent, all rows) − $18,054,247.62 (child) = $443,889.62 = SGR $403,889.62 + two superseded originals ($30,000 + $10,000); contributions gap $1,000 (Stearns superseded); gifts gap $250 (Margaux Kelly — truly absent from `qpit-abzn`, the amendment carries no gift row either).

**Structural absences (flag=true, zero child rows):** 7 parent envelopes; 6 are superseded originals whose list rows exist only under the amendment envelope; 1 is a real gap — **SGR Consulting, LLC Quarterly Report 9-1-2024 (`9baff337…`, $403,889.62 on the parent, nothing in `m75g-xpci`)**; the identical amount with 2 client lines sits under SGR's later Termination envelope `5f220ed6` (signed 2025-09-24). Reverse: one Storefront Political Media envelope (`97ea51ea…`, Q 3-1-2025, every parent flag false, every total 0) plants a key-only phantom row in ALL 8 child tables — a canary for the exporter's "blank section still writes a row" behavior; the three 1-row city-side tables and their two joined views ARE that phantom. Also 13 parents `hasclients=true` with total 0 (12 have null/zero child rows) — the flags mean "section touched", not "money reported"; 3 rows `didconsultantmakecontributions=false` with `totalcontributions>0` (2 by the itemized subtotal — depends which column).

**Name fragmentation:**
- Consultants (`campaignconsultantname`): 90 raw → 78 after mechanical normalization (case/punct/LLC/Inc/The/&) → ~71 real after 7 hand clusters ('CS Communications'/'CS Communiations', 'Ammplify'/'Amplify Campaigns LLC', 'BMWL Campaigns'/'BMWL, Inc', 'Joseph Sweiss'/'Outset Strategies', three Paul Kumar forms, three Tyler Law/Thematic forms, John (J) Gallagher). `typeofcampaignconsultant` is per-filing (Entity 204 · Person 56): 12 names appear as both.
- Clients (`clientlist_clientname`): 118 distinct strings; mechanical normalization collapses only to 111; the rest is real drift — Farrell 7 spellings/13 rows/$4.54M ('Farrel', 'Farrel 2024'), Lurie 6/19/$4.13M, Breed 7/8/$1.40M ('Re-lect'), Yes on B 5, Yes on C/No on D 6, Engardio recall 4. `GROUP BY clientlist_clientname` is meaningless without a crosswalk.
- `acwz-2ua3`: 58 raw consultant names → ~53; 3 rows have the CLIENT name typed into the consultant field; Storefront filed the same five terminations twice under variant client names, both 'Original'.

**Structured ids: NONE.** `columns.json` for `iv34-5p9x`, `m75g-xpci`, `acwz-2ua3`, `7gkm-68qf` carry no fppc/committee/filer id — only `envelope_id`/`entry_id` and free text. Every join to campaign-finance data is name-only and fuzzy. Resolution result: 102 of 118 client strings / 165 rows / $17,318,195.50 (96% of dollars) resolve to a registered SFEC committee in `4c8t-ngau`/`pitq-e56w` — but only 58 mechanically; 42 needed fuzzy + human review; 2 ('Yes on B' $296,268 Stearns; 'ESER' $20,000 Bedford Grove) resolve only by reading the consultant's `acwz-2ua3` authorization. ~65 distinct committees behind those. Plus: 9 bare candidate names / $285,873 (Danny Sauter $108,195, Brandee Marckmann $104,361, …); 2 non-SF state committees / $164,479 (Scott Wiener for State Senate 2024 $156,979; Rafael Mandelman for Senate 2028 $7,500) — the Wiener one reconciles to the cent in `3n88-2rrb`; 1 resolved-by-money inference ('San Franciscans Opposed to Aaron Peskin for Mayor 2024' $81,500 — no such filer, but 'Residents Opposing Aaron Peskin for Mayor 2024' paid Strother Nuckels exactly $81,500 in the same quarter); **4 unresolved / $204,200** ('Caesar Kamila' $152,000 on the junk Emelia Rosie Washington registration; three 'Strong(er) Muni for All' spellings $52,200 with no registered filer as of 2026-08-14).

**Filing calendar (statutory, C&GCC §1.500 et seq.; source: the SFEC guidance page):** quarterly reports due **Mar 15 / Jun 15 / Sep 15 / Dec 15** for periods Dec–Feb / Mar–May / Jun–Aug / Sep–Nov, rolling to the next business day on weekends/holidays; re-registration by **Jan 1**; client authorization within **15 days** of retention; client termination within **30 days**; fees $50/$200/$400 tiers + $50 per client. Against that calendar, **43 of 172 quarterlies (25%) were signed after the deadline** (7 more than 30 days late, 3 more than 90: Rodney Leong's Sep–Nov 2024 quarterly signed 2025-07-16 = 212 days; The Outreach Team 168; Paul Kumar 92); median 1.5 days EARLY; 15 were signed before their period even ended (the mis-keyed rows). Quarterlies received per period: Sep-2024 24 · Dec-2024 22 · Mar-2025 19 · Jun-2025 21 · Sep-2025 22 · Dec-2025 21 · Mar-2026 34 · "2026-12" mis-keyed 9. `acwz-2ua3` (raw rows): terminations median 23 days after termination date (20 of 65 past the 30-day rule, max 184), authorizations median 14 (25 of 65 past 15 days, one filed 15 days BEFORE its start).

**The "expected" denominator cannot come from the family alone.** 40 raw names filed a 2026-period quarterly but only 31 have a 2026 Reregistration/Initial Registration in `iv34-5p9x` — ≥12 filers (Bedford Grove/Celeste Wolter Sempere, CliffordMoss, Growth Political Strategies, Jamie Hughes, Joseph Arellano, MJE Strategies, Nathan Allbee, Otto Pippenger, Proverb Strategy Advisors, Storefront Political Media, The Campaign Workshop, CS Communications) have no 2026 registration in the family; across all periods 35 of 69 quarterly/termination filers (mechanically normalized) have NO registration row at all. Either they file quarterlies while lapsed or registrations live outside DataSF — a reportable lead AND the reason "expected" must be defined as *filed anything in the trailing 12 months and not terminated*, with the paper index `an34-qeyq` for 2024.

**Privacy / redaction (the memo's rule set):** every parent row carries `campaignconsultantinformation_phone` (260/260); `acwz-2ua3` `clientinformation_clientbusinessphone` 130/130; vendor phone 8/9. For the 56 Person-type filings the "business address" is usually a HOME address (28 of 35 distinct Person addresses lack a suite/PO-box marker; explicit 'Apt' rows). `gjyg-9whd` names 75 private individuals. Rule: never render phone columns; Person addresses at city level only; employees as counts by default; gift beneficiaries are public officials so names are fair; project with `$select` so PII never crosses the wire (`iv34-5p9x` unselected is 563 KB / 2.8 s for 260 rows because of 45 columns of addresses/phones). Note `acwz-2ua3` has license None (all others PDDL) for the About colophon.

**Every other concrete trap, one bullet each:**
- The three city-side sections are 0-for-260 (`citycontracts_hascitycontracts`, `cityappointments_hascityappointments`, `employmentoflocalofficeholdersandcityemployees` all false; `sum(citycontracts_total)` = 0). Render "no filer has ever reported this", never an empty chart.
- 9 Quarterly rows carry reporting period 2026-12-01→2027-02-28 but were signed 4–22 March 2026 (Jamie Hughes $20,000, Bedford Grove $25,000, Nathan Allbee $24,000, The Media Company $10,000 ×2, Growth Political …) — the Dec 2025–Feb 2026 quarter mis-keyed a year forward; 6 more Quarterly rows have periods wholly in the future at signing. ## 8. Recommendation

**What to build:** not a standalone "Campaign Consultants" view. The tables are too small (260 / 185 / 30 / 9 / 7 / 1 / 1 / 1 / 94), have no geography, and would read as an empty dashboard. Build a **Consultants lens inside CampaignFinance** whose hero is the two-sided reconciliation: for each registered consultant (or, flipped, each committee), consultant-reported receipts per reporting quarter beside committee-reported Schedule E payments in the same window, with the ratio, the exact-match count, the unmatched remainder in each direction, and an explicit "awaiting committee filing" state for quarters not yet complete on the pitq side. Below it: the client network (consultant ↔ committee, dollars, quarter), the roster (registrations/re-registrations by year, employees as counts, "filed a quarterly with no registration on record" as a flag), the contributions cross-check (consultant contribution → matched Schedule A/497 receipt, self-dealing flag when recipient is a paying client), and the signed-PDF link per filing. Enrich the existing entity panels with `4c8t-ngau` status/type/candidate name and `9ggq-m8hp` ending cash / YTD totals now — that part is free.

**Precompute, don't live-join.** A live reconciliation costs one `pitq` payee `LIKE` query per consultant (0.5–0.8 s each; top-10 = 10+ requests against the browser's ~6 per-host slots) plus the family pulls (parent projected with `$select`; `m75g-xpci` 53 KB / 0.7 s; window-function dedupe 0.59 s). Commit the reconciliation as a generated JSON from a probe script (the RCV `reconciliation.test.ts` pattern), and poll `max(:created_at)` on the family for a cheap "filed today" signal.

**Two authored crosswalks are prerequisites**, committed as data with pinning tests: (1) consultant aliases (90 raw → ~71; plus the DBA/affiliate bridges to pitq payee names: Kazin↔Canal Partners Media, KMM↔Kully Hall LLC, Bedford Grove↔Celeste Wolter Sempere — each marked inferred; **Stearns↔Rough House scoped to Stearns's own clients, never global**); (2) client string → `filer_nid` (118 strings → ~65 committees, with the 9 bare-candidate, 2 state (one reconciled via `3n88-2rrb`), 1 resolved-by-money, 4 unresolved classes explicit and their provenance labels matching the counts). A standing test should re-run the join-integrity and conservation checks (0 orphans; child sums == parent totals), the latest-version rule as *(rows − superseded) == distinct filingseries*, and the restatement collapse, against live DataSF.

**Query contract:** always join child→parent on `envelope_id`; dedupe to `MAX(datesigned)` per `filingseries` (window function or GROUP BY + client join) — on `acwz-2ua3` too; drive money from the child tables, never parent totals; collapse Termination/Quarterly restatements by NORMALIZED consultant name + period start, and state a rule for inexact pairs (keep the later-signed report; disclose the delta); assign undated Schedule E rows by filing-period overlap; filter placeholder rows on amount `IS NOT NULL`; booleans `= true`; treat has-flags as "section touched"; project with `$select` (no phone columns ever).

**What it must disclose (in-view, About, data-insights):** coverage begins Sep–Nov 2024 (74% of dollars in that one quarter — an election artifact, not a trend); the amendment rule, its `filingseries` caveat, and the restatement collapse (5 exact + 2 inexact + AGENCY); the SGR $403,889.62 parent-only envelope; that consultant and client identities are hand-authored crosswalks with a listed unresolved remainder; that reconciliation is by money and window, "in-window" mismatches within days are timing not omission, gross-vs-fee reporting is legitimately inconsistent, and the committee side lags by up to a semiannual; the statutory calendar and that "filed after deadline" is a per-filing measured fact (43 of 172) while dates and periods are filer-entered; the AGENCY correction; the two junk filers; that the three city-side sections have never been answered "yes" by anyone (rendered as a sentence, not a chart); the Sep 2023–Aug 2024 structured hole and that any legacy splice shows it as absent; the redaction rule.

**What to withhold:** gifts (`qpit-abzn` — 7 rows, mostly re-reported contributions, dominated by two dubious filers), vendors (9 rows), the three empty city-side tables as tables, trend charts on any table under ~100 rows, a per-consultant "late filer" SCOREBOARD (the per-filing fact is fine; a leaderboard on filer-entered dates and mis-keyed periods is not), any map (business addresses are treasurer/compliance firms, out-of-state offices, and home addresses), phone numbers and Person addresses below city level, employee names by default, and any per-`filingseries` time axis (the suffix is text and mis-keyed).

**What NOT to build:** an automatic live name join (it will silently mis-attribute — 'Gary Mc Coy' vs 'McCoy', two `filer_nid`s for Kim for School Board, Rough House as Stearns); a continuous 2009→2026 line across the legacy/new seam without the hole; anything that sums `iv34-5p9x` totals raw; a CNS-code-only view of consultant money (703 rows / $6.08M misses most of it); the DataSF joined views as the source of truth (they inherit latest-only by accident, not by logic); an "expected vs received" denominator taken from the family's own registrations (35 of 69 filers have none).

## 9. Method notes for reuse

- Discovery: `https://data.sfgov.org/api/catalog/v1?domains=data.sfgov.org&search_context=data.sfgov.org&q=…` — BOTH params or it federates the whole Socrata network; page it (q=SFEC returns 113). Confirm `.id` on every `api/views/<id>.json` you save; per-dataset filenames.
- `columns.json` `cachedContents.cardinality` on these DocuSign-family tables equals the row count for every column — measure with `count(distinct …)`; null/non_null/top are fine. pitq's cached row count (941,345) lags live (971,129).
- Derived views: `.query` is `{}` and `.metadata.jsonQuery` null — the join lives only in `.queryString`; read it for WHERE/DISTINCT/GROUP before trusting a "joined view".
- `data.sfgov.org` accepts window functions and `|>` chained subqueries on `iv34-5p9x` (`row_number() OVER (PARTITION BY … ORDER BY …)`); verified there only — keep the GROUP BY + client-join fallback.
- Cadence is measurable from Socrata system fields: `$select=…,:created_at,:updated_at` (real UTC) against `datesigned` (SF-local) — sign→publish lag, append-only proof, and change detection all come from those two columns.
- Checkbox columns: `= true`/`= false` only. Empty string `''` vs null is inconsistent inside one address block — test both. Money arrives as strings; legacy money as `'$x,xxx.xx'` text.
- Aggregate rankings: add `IS NOT NULL` or the null group sorts first under `DESC`.
- Two-sided reconciliation recipe: dedupe to latest envelope; join clients→parent; hand-map client strings → `filer_nid`; pull `pitq-e56w` `record_type in ('EXPN','DEBT')` for the payee name family with `filing_date >=` the era start; sum Schedule E `transaction_amount_1` (`== calculated_amount`) inside the consultant's reporting window, keep Schedule F/G separate and label any E+G figure as such; say which date field a citywide filter uses (`transaction_date` vs `filing_date` differ by 343 rows / $1.5M on CNS); when a name returns nothing, search the committee's top payees for the exact dollar amount; state committees → `3n88-2rrb`. Contributions: `RCPT`/`S497` rows for the recipient ±30 days, exact amount, then contributor/principal name.
- Checkbook/contract sweeps: hand-authored `upper(vendor) LIKE` families per consultant; read every hit by eye — 17 of 69 families hit and only 1 was real.
- Legacy quarter grammar is offset (Dec–Feb = Q1 of the February year); never `date_extract_q`.
- Every figure here was re-derived at least twice (cross-check + verifier) against live SODA on 2026-08-14; the numbers verifier reproduced every row count, span, child sum, join/conservation result and the big two-sided components to the cent. Scratch scripts lived in the session scratchpad (`sfec-recon/{amendments,join-integrity,two-sided,clients-vs-filers,city-cross,verify-*}`) and are not committed — the recipes above are what to rebuild from.
